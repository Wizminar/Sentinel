    How grading works
    
        
    Every site starts at 100. Each check takes points away for what's missing or misconfigured, up to a limit, so one bad header can't outweigh everything else. Bonuses for extra-strong setups only count once a site is already at 90 or above — they reward polish, they can't hide a gap.
    
        
    Some problems cap the grade regardless of the arithmetic: a page served over plain HTTP can't score above D, and a server that lets any site read logged-in users' data gets an F.

      Catch regressions before they ship
      
        
      The same engine runs as a command-line tool and a GitHub Action. Point it at a preview deploy and the build fails when someone drops a header. Findings show up as annotations on the pull request, or as SARIF in GitHub code scanning.
      
      
      
      
      
        
        
      
      
    
      

    
      
      
      What a header scan can't see
      
      
        
        
      • One response. Sentinel checks the URL you give it, with one GET request and no login. Other routes, API responses and signed-in pages can send different headers.
        • 
        
      • Policies set in HTML. A CSP in a <meta> tag isn't read. Neither is anything set by JavaScript after load.
        • 
        
      • Everything below HTTP. TLS versions, ciphers, certificates and DNS records need their own tools.
        • 
        
      • Your actual code. A perfect CSP doesn't remove an XSS bug; it makes it much harder to exploit. Headers are one layer.
